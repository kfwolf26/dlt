# 预测模型重构：序号级连续命中杀号

## Context

当前 [prediction_model.py](file:///d:/ai/ssq/modules/prediction_model.py) 的预测模型是"预测者级聚合判定"：每个预测者预测 8 个红球杀号(排序) + 1 个蓝球，若整个杀号集连续 ≥ min_streak 期"对"（杀号都不在开奖红球中），则下一期该杀号集作为最终杀号。

用户要求改为"序号级独立判定"模型：
1. 每名预测者预测 **N 个前区号码 + M 个后区号码**（数量可设置），号码按生成顺序保留序号（不排序）
2. "对"的语义反转为 **命中对**（预测数字 ∈ 开奖号码）
3. 某预测者某序号位置连续 ≥ min_streak 期"对" → 新一期该序号位置的预测数字为杀号

这是粒度从"整体"细化到"序号位置"的重构，且"对"的语义从"杀号准(不出)"反转为"命中准(出现)"。旧 prediction_data.json (38MB) 结构不兼容，直接覆盖重生成。

## 方法修改清单

### `_generate_one_predictor(pid, front_count, back_count)`
- 签名从 `(pid, kill_count)` 改为 `(pid, front_count, back_count)`
- `front = random.sample(RED_ALL, min(front_count, 33))`（不 sorted）
- `back = random.sample(BLUE_ALL, min(back_count, 16))`（不 sorted）
- 返回 `{"predictor_id": pid+1, "front": [...], "back": [...]}`

### `_generate_predictions`
- 读取 `front_count_var`/`back_count_var`
- 校验：`front_count>33`/`back_count>16`/`<=0` 分别报错
- params 删除 `kill_count`，新增 `front_count`/`back_count`
- 调用 `_generate_one_predictor(pid, front_count, back_count)`

### `_add_predictions`
- 读取 `params.get("front_count",8)`/`params.get("back_count",4)`
- 调用点同步新签名

### `_query_predictor_data`
- 读取 `pred.get("front",[])`/`pred.get("back",[])`
- 命中判定（聚合）：
  - `front_hit = all(n in red_result for n in front)`
  - `back_hit = all(n == blue_result for n in back)`
- 展示：前区/后区按序号顺序空格分隔两位补零

### `_refresh_results`
- 字段名 `red_remain`→`front_remain`、`blue_pred`→`back_remain`、`red_hit`→`front_hit`、`blue_hit`→`back_hit`
- 命中判定逻辑等价平移

### `_calc_prediction_stats`
- 局部变量与字段读取同步改名
- 文本：红球命中→前区命中、蓝球命中→后区命中、红蓝双中→前后区双中
- 弹窗 tree 列：`red_remain`→`front_remain`、`blue_pred`→`back_remain`、`red`→`front`、`blue`→`back`

### `_calculate_kill_numbers` ★ 核心重构
**算法**：
```
# 预缓存（性能优化：避免180万次重复 _parse_result）
history_red = {issue: set(red_result) for issue in history_issues}
history_blue = {issue: blue_result for issue in history_issues}

for pid in range(predictor_count):
    next_pred = next_predictors[pid]
    # 前区：每个序号独立算 streak
    for i in range(front_count):
        kill_num = next_pred["front"][i]
        streak = 0; hit_count = 0; streak_active = True
        for issue in history_issues:  # 已 reverse=True，从新到旧
            num = predictions[issue]["predictors"][pid]["front"][i]
            hit = num in history_red[issue]
            if hit:
                hit_count += 1
                if streak_active: streak += 1
            else:
                streak_active = False   # streak 冻结，hit_count 继续累加
        if streak >= min_streak:
            front_kill_set.add(kill_num)
            front_kill_details.append((pid+1, i+1, kill_num, streak, f"{hit_count}/{total_periods}"))
    # 后区：同理，hit = (num == history_blue[issue])
    ...
```

**关键点**：
- `history_issues` 已 `sorted(reverse=True)`，从最新期向旧遍历
- streak 遇第一个"错"冻结（用 `streak_active` 标记），hit_count 全量累加（用于历史命中率）
- 杀号去重：`front_kill_set`/`back_kill_set` 用 set 自动去重
- 排序：`details.sort(key=lambda x: (-x[3], x[0], x[1]))`（streak降序、pid升序、seq升序）
- 剩余：`front_remain = sorted(set(RED_ALL) - front_kill_set)`，`back_remain = sorted(set(BLUE_ALL) - back_kill_set)`

**update_ui**：
- `red_kill_tree` 填 `front_kill_details`，`blue_pred_tree` 填 `back_kill_details`
- label 文本：前区/后区杀号对应预测期数...
- 成功弹窗：`前区剩余：{len(front_remain)}个\n后区剩余：{len(back_remain)}个`

### `_save_remain_numbers`
- 解析 `red_remain_text` → `front_remain` 列表，`blue_remain_text` → `back_remain` 列表
- 命中判定字段名同步改
- `new_record` 字段名同步改

## 边界情况

1. `front_count>33`/`back_count>16`/`<=0`：在 `_generate_predictions` 弹错并 return
2. predictor 中 `front`/`back` 长度不符：循环用 `if i >= len(list): break` 防越界
3. 新一期未生成：保留原校验 `if not next_issue or next_issue not in predictions`
4. 历史数据为空：保留原校验 `if total_periods == 0`
5. `min_streak<=0`：新增校验弹错
6. 旧 prediction_data.json 兼容：`_load_prediction_data` 后检测，若 params 含 `kill_count` 无 `front_count`，弹提示让用户重新生成
